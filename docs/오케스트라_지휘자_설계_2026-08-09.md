# 지휘자(Conductor) 설계 — 선택적 에이전트 호출·중복 금지

> **문서명:** 오케스트라_지휘자_설계_2026-08-09  
> **버전:** v1.0  
> **목적:** 조서에 **존재하는 계정**에 대해 **꼭 필요한 에이전트만** 호출하고,  
> L1 규칙엔진·기능 에이전트·계정 에이전트 간 **동일 작업을 중복하지 않도록** 지휘한다.  
> **선행:** 「멀티에이전트_아키텍처_설계안_2026-08-09」·테스트 시 장시간 대기 이슈

---

## 1. 한 줄 정의

**지휘자(Conductor / Lead Reviewer Controller)** 는  
「악보(조서 계정·시트 맵)를 읽고 → 어느 연주자(에이전트)를 세울지 결정 → 누가 어떤 악절을 맡는지 지시 → 중복 연주를 금하고 → 최종 합주를 조율」하는 역할이다.

오케스트레이터가 *실행기*라면, 지휘자는 *작업계획·권한·금지*를 먼저 정하는 **컨트롤러**다.

```
업로드 조서
    │
    ▼
┌─────────────────────┐
│ ① ScoreReader       │  계정·조서코드·표 수·금액열 유무 스캔
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│ ② Conductor         │  WorkPlan 작성 (호출 목록·금지·소유권)
│    (지휘자)          │  after_L1 / standalone 모드
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│ ③ Orchestra         │  WorkPlan에 있는 에이전트만 병렬 실행
│    (오케스트레이터)   │
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│ ④ Concertmaster     │  상호검증·중복제거·Tier 조율·감사추적
└─────────────────────┘
```

---

## 2. 왜 필요한가 (현재 문제)

| 현상 | 원인 |
|------|------|
| 리뷰가 수분~수십 분 | AI 시트 전수 + FA가 L1과 **같은 체크리스트를 다시** 돌림 |
| CPU는 낮은데 화면만 대기 | API/중복 I/O 대기 + 진행표시 부재 |
| 에이전트 “전원이 항상 출동” | 조서에 없는 계정·이미 L1이 끝낸 작업까지 호출 |

**원칙:** *많을수록 좋은 에이전트가 아니라, 필요한 악장만 연주하는 지휘.*

---

## 3. 소유권(Ownership) — 중복 금지의 핵심

한 작업은 **한 명의 주인**만 갖는다. 다른 에이전트는 보강만 하거나 **호출하지 않는다**.

| 작업 | 기본 소유자 | after_L1 모드에서 Conductor 지시 |
|------|-------------|----------------------------------|
| 4대 중점 자가진단 전수 | **L1** `focus_selfcheck` (G0~G4) | FA-4 **금지(전수)** — red-flag 역매칭만 허용. 구엔진 `fss_focus`는 폴백 |
| 감리지적 체크리스트 전수 | **L1** `enforcement_review` | FA-4 **금지(전수)** |
| Lead·주석·교차합 대사 | **L1** (기본) | FA-2 **스킵** (고도화 로직 붙기 전) |
| 표 합계·재계산 | **L1** | after_L1에서 **FA-1 전수 생략** (36시트 재계산이 수분 소요되는 병목). standalone만 계정·표 상한으로 실행 |
| 필수절차 카탈로그 Pass/Fail | **FA-3** | 조서에 있는 계정만 |
| 계정 고유 함정 | **AA-xx** | 해당 계정 시트 있을 때만 |
| 시트별 서술형 AI | **AI** (선택) | Conductor가 *대상 시트 상한·우선순위* 지정 |

## 4. 계정 → 필수 에이전트 라우팅표 (악보)

조서에 **실제로 존재하는 계정**만 행을 활성화한다.

| 계정 (canonical) | 필수 | 조건부 | 호출 금지(after_L1) |
|------------------|------|--------|---------------------|
| 현금및예금 | FA-3, AA-01 | FA-1(금액표) | FA-4 전수, FA-2 |
| 매출채권 | FA-3, AA-02 | FA-1 | 〃 |
| 재고자산 | FA-3, AA-03 | FA-1 | 〃 |
| 유형/무형자산 | FA-3, AA-04/05 | FA-1 | 〃 |
| 투자자산 | FA-3, AA-06 | — | 〃 |
| 차입금 | FA-3, AA-07 | FA-1, FA-2(이자테스트 시트 있을 때) | FA-4 전수 |
| 충당/우발 | FA-3, AA-08 | FA-4 red-flag | FA-4 전수 |
| 매출 | FA-3, AA-09 | FA-1 | 〃 |
| 법인세·자본·특수관계·리스·계속기업 | FA-3 + 해당 AA | — | 〃 |
| (공통) | FA-4 **red-flag만** | — | 체크리스트 전수 |

**FA-1 조건부:** 숫자 열이 2개 이상인 표가 있을 때만.  
**FA-2 조건부:** `조서연결_대사_사전`에 매핑된 역할 시트가 있고, L1이 해당 검사를 안 했을 때만 (현재 after_L1에서는 기본 스킵).

## 5. WorkPlan 스키마 (지휘자 지시서)

```json
{
  "mode": "after_L1",
  "accounts": ["재고자산", "현금및예금"],
  "call": ["FA-1", "FA-3", "FA-4:redflag", "AA:재고자산", "AA:현금및예금"],
  "skip": ["FA-2", "FA-4:checklists"],
  "reasons": {
    "FA-2": "L1이 교차대사·주석참조를 이미 수행",
    "FA-4:checklists": "L1이 4대중점·감리지적 전수 수행"
  },
  "max_workers": 6,
  "ai_sheet_cap": 12
}
```

Conductor는 이 계획만 Orchestra에 넘긴다. Orchestra는 `call`에 없는 에이전트를 **절대 실행하지 않는다**.

## 6. 지휘 흐름 (단계)

### Step 0 — Score (악보 읽기)
- `document_accounts(doc)`
- 시트코드·금액표 여부·표 개수
- `mode`: app이 이미 `run_review`를 돌렸으면 `after_L1`, 단독이면 `standalone`

### Step 1 — Plan (배치)
- 라우팅표로 `call` / `skip` 생성
- 감사추적에 「왜 이 에이전트를 세웠/빼었는지」 기록

### Step 2 — Rehearse (병렬 연주)
- `call`만 ThreadPool 실행
- FA-4는 `include_checklists=(mode==standalone)`

### Step 3 — Concertmaster (조율)
- 상호검증(AA 단독 상 → 중 하향)
- 서명 기반 중복 제거
- 근거 없는 Tier1 하향
- ID 배정

### Step 4 — Report
- findings + audit_trail + **work_plan** (대시보드·엑셀에 “이번에 호출한 에이전트” 표시 가능)

---

## 7. AI와의 관계 (시간 폭탄 제거)

AI는 오케스트라 전원이 아니다. Conductor 규칙:

1. 기본 **OFF** (빠른 심리 = L1 + 선택 에이전트)
2. ON이어도 **우선 시트만**: 중점계정·Fail 난 시트·본문 긴 시트 상위 N장 (`ai_sheet_cap`)
3. L1·MA가 이미 “상”으로 잡은 동일 쟁점은 AI에 **재질문하지 않음** (향후)

## 8. 성공 지표

| 지표 | 목표 |
|------|------|
| 단일 계정 조서(재고 1파일) | L1+Conductor **&lt; 5초** (AI OFF) |
| 8파일 묶음 | AI OFF **&lt; 30초** |
| after_L1에서 FA-4 체크리스트 전수 | **0회** |
| 조서에 없는 계정 AA 호출 | **0회** |
| audit_trail에 skip 사유 | **항상 기록** |
